# Wanscam / Hipcam `ipc_server` — статический разбор CGI и резервной копии

**Объект:** `/mnt/mtd/ipc/ipc_server` из предоставленного владельцем 16-МиБ MTD-образа Wanscam.

**Метод:** offline ELF ARM32 static analysis (`readelf`, LLVM ARM disassembler, просмотр `.rodata`, сопоставление с тремя локальными `.bin` резервными копиями). **Никаких команд или записей на камере этот этап не выполнял.** В документе отсутствуют содержимое `/etc/shadow` и найденные пользовательские пароли.

## 1. Что представляет собой `ipc_server`

- ARM ELF32, little-endian, dynamically linked with `/lib/ld-uClibc.so.0`, размер ~1,7 МиБ.
- Хотя файл помечен `stripped`, в его динамической таблице символов **сохранились названия многих функций**. Поэтому мы можем непосредственно связать имена и адреса обработчиков, не только гадать по строкам.
- Значимые символы (виртуальные адреса в ELF):

| Адрес | Символ | Назначение по коду |
|---|---|---|
| `0x00044010` | `HI_CGI_Backup` | Формирование и выдача конфигурационного архива |
| `0x00044288` | `HI_CGI_Restore` | Приём и развёртывание архива конфигурации |
| `0x00044388` | `HI_CGI_Upgrade` | Приём пакета обновления |
| `0x0004362c` | `HI_CGI_RecvMultipartFormData` | Приём `multipart/form-data`, общая проверка заголовка/хвоста |
| `0x0004355c` | `HI_CGI_InitCfg_Verify` | Проверка 48-байтной декодированной структуры |
| `0x000432f0` | `HI_CGI_InitCfg_CheckFileName` | Проверка имени / типа / версии файла |
| `0x00030d20` | `HI_CGI_Telnet_Cfg` | Внутренняя обработка диагностической функции Telnet |
| `0x0002e118` | `HI_CGI_Interface` | Центральный CGI интерфейс |

## 2. Формирование резервной копии — `HI_CGI_Backup`

В `.rodata` и коде функции подтверждены:

```text
/mnt/mtd/ipc/conf
/mnt/mtd/ipc/exclude.lst
/mnt/mtd/ipc/tmpfs/config_backup.bin
tar -czf %s -X %s %s
ab+
```

Таким образом, штатный `backup.cgi` создаёт **GZIP-сжатый TAR конфигурационных файлов**, а не копию ядра/rootfs. Используется исключающий список `exclude.lst`.

### Формат 128 байт после GZIP

Сопоставление кода `HI_CGI_Backup` (`0x44010–0x44288`) с тремя предоставленными резервными копиями:

| Смещение относительно начала хвоста | Длина | Содержание |
|---|---:|---|
| `0` | 4 | Little-endian `0x00000040` = длина Base64-строки, **64 байта** |
| `4` | 64 | Base64 48-байтной бинарной структуры |
| `68` | 60 | Часть 128-байтного буфера, заполненная псевдослучайными байтами через `rand()` |

Код `HI_CGI_Backup` вызывает `gettimeofday()`, `srand()`, `rand()` и `libs_base64encoder_ex`; после генерации буфера записывает в архив **ровно 128 байт** (`fwrite` с `size=128, count=1`). Base64-строка поверх буфера располагается начиная с байта 4.

Декодированные 48 байт начинаются со значений:

```text
uint32_le type  = 0x00001001  # backup / restore configuration
uint32_le magic = 0x46567868
```

Второй оригинальный бэкап имеет **такую же 48-байтную структуру**, но другие 60 байт в конце хвоста. Модифицированный архив с Telnet сохраняет исходные значения структуры.

**Это не криптографическая подпись TAR.** Последние 60 байт генерируются через `rand()`, а не вычисляются от архива. В 48-байтном блоке находятся фиксированные поля для проверки формата/платформы. Мы **не нашли** в соответствующей функции вычисления хеша содержимого TAR или MAC-подписи.

## 3. Восстановление — `HI_CGI_Restore`

Точка входа `0x44288`. Функция вызывает общий `HI_CGI_RecvMultipartFormData` с типом `0x1001`, а далее использует штатные системные операции; в `.rodata` присутствуют:

```text
/mnt/mtd/ipc/tmpfs/config_restore.bin
tar -xvzf %s -C /
rm %s
```

После удачного пути обработки инициируется перезапуск камеры через `HI_CGI_SysReboot`. Это согласуется с наблюдаемым ранее ответом `restore succeed.` на загрузку модифицированной конфигурации.

`HI_CGI_RecvMultipartFormData` в ходе приёма архива читает хвост и вызывает `HI_CGI_InitCfg_Verify` по адресу `0x43a44`. Эта функция (`0x4355c`) декодирует **64-байтную Base64-строку в 48 байт** и проверяет минимум:

1. длина декодированного блока **ровно 48**;
2. первое 32-битное поле совпадает с типом операции (`0x1001` для конфигурации, `0x1002` для пакета обновления);
3. второе 32-битное поле равно `0x46567868`.

Таким образом, реальная проверка хвоста **есть**, но по исследованному коду это проверка идентификаторов формата и вендора, **не проверка целостности архивного содержимого**. Она объясняет, почему изменение `tenable` с сохранённым старым хвостом успешно прошло восстановление.

Для пакета обновления существует **отдельный путь проверок** (`HI_CGI_InitCfg_CheckFileName`, версия/расширение `.pkg` и другой тип `0x1002`); приведённый вывод о конфигурационных архивах **нельзя автоматически переносить на проверку firmware upgrade**.

## 4. Telnet

- `HI_CGI_Telnet_Cfg` (`0x30d20`) — реально присутствующая функция; её код сопоставляет ключи (`syscfg`, `-act`, `list`, `set`) и при определённом разрешённом запросе содержит путь выполнения строки `telnetd&`.
- Но **наличие функции в ELF не доказывает**, что соответствующий CGI-маршрут доступен через публичный `param.cgi` в данной сборке или что он разрешён текущему пользователю. Ранее `getdebugattr` и `setdebugattr` возвращали `invalid request`.
- Работающий и проверенный механизм включения Telnet на этой камере — настройка `tenable = "1"` в `config_debug.ini`, считываемая загрузочным скриптом `/mnt/mtd/ipc/run`.

## 5. Риски и итог

- **Конфигурационный архив не подписан криптографически в исследованном пути `backup.cgi` → `restore.cgi`**; его нельзя считать доверенным или защищённым от модификаций.
- Уязвимость практически значима в первую очередь при наличии доступа к защищённому обработчику восстановления — без прав доступа к HTTP CGI утверждать удалённую эксплуатацию нельзя.
- `restore.cgi` выполняет распаковку TAR на корневую файловую систему, и такой механизм потенциально опасен при подаче неподходящих файлов. Мы **не проводили** активных испытаний с внедрением произвольных файлов и **не утверждаем**, что в этой сборке доказана возможность записи вне ожидаемого каталога.
- Оригинальный 16-МиБ образ не модифицирован; полноценную прошивку **не** загружали обратно; всё исследование сделано офлайн.
- После завершения нужных работ отключить Telnet и закрыть TCP 23. Даже с отключённым Telnet, исходная старая HTTP-служба заслуживает изоляции в отдельной CCTV-сети.

## 6. Команда для воспроизведения статического анализа (Linux с LLVM)

```sh
llvm-objdump -d --start-address=0x44010 --stop-address=0x44388 ipc_server
```

Для независимого исследования хвостов:

```powershell
py .\wanscam_backup_trailer_inspect.py .\wanscam_backup.bin .\wanscam_backup_2.bin
```

Дополнительно: `wanscam_accounts_local.py` извлекает `root`/`admin` **только на локальном ПК**, опционально проверяет свои словари/кандидатов по MD5-crypt и сохраняет результаты приватно; он не подключается к Telnet/HTTP камеры.
